# C-3 K&R C re-run, 2026-11-18

This re-runs, by name, every C target that the 2026-07-28 campaign sweep
(`results-0728`) reported as K&R C: `K&R C: legacy dialect — discovered and
statically analyzed, not fuzzed`. That is the C-3 class of
[expected-gaps.md](../expected-gaps.md). Each project is re-run at the commit
that sweep measured. The bhf under test is a release build of the wave-11
branch, which fuzzes a K&R definition through the prototype its parameter
declarations give (#283).

The rows are under `benchmarks/campaign-2026-07-25/`:

| Directory | What it is |
|---|---|
| `results-0728/` | Before: the 2026-07-28 sweep |
| `results-1118-c3/` | After: the 20 targets, in 9 projects |

## Reproduce

```sh
cd benchmarks/campaign-2026-07-25
BHF_BIN=<bhf> python3 go1_rerun.py results-0728 results-1118-c3 \
  --lang c --class C-3 --all-lanes
```

`--all-lanes` reads every lane's rows. Most of these targets are in projects
the sweep chose for another language: zlib inside AdaCore/aws, the lemon
parser generator inside a Fortran project, secp256k1 inside go-ethereum.

## Before and after

| | Before | After |
|---|---:|---:|
| C-3 targets re-run | 20 | 20 |
| Report-only as K&R C | 20 | 0 |
| Built and fuzzed | 0 | 4 |
| Built, the target never entered | 0 | 1 |
| Failed to build | 0 | 7 |
| A parameter bhf cannot decode | 0 | 7 |
| Report-only for another reason | 0 | 1 |

Only 6 of the 20 are K&R definitions. The other 14 are ANSI C in files the
July extractor read as K&R, from ANSI `(void)` prototypes and commented-out
examples. That extractor has been fixed since (see
[sweep-500](../site/sweep-500.md)), so they now take the ordinary C path and
stop where other C targets stop.

The 6 K&R definitions, after:

| Project | Target | After |
|---|---|---|
| AdaCore/aws (zlib) | `inflateInit2_` | built and fuzzed |
| mapmeld/fortran-machine (lemon) | `Parse` | built and fuzzed |
| mapmeld/fortran-machine (lemon) | `OptInit` | built; no input passed the argument decoding into the target |
| AdaCore/aws (zlib) | `read_buf` | failed build: zlib's `#define local static` (#415) |
| AdaCore/aws (zlib) | `gz_load` | failed build: the same (#415) |
| nwchemgit/nwchem | `c_read` | no definition in the active build: an inactive `#if` compiles it out |

The 14 ANSI targets, after:

| What stops them | Targets |
|---|---:|
| Built and fuzzed (lemon's `merge` and `msort`) | 2 |
| A parameter of an opaque project type (`OSSL_LIB_CTX *`, PostgreSQL's `PG_FUNCTION_ARGS` and `Size`, Perl's `pTHX_ PerlIO *`) | 6 |
| The project's own headers or the PostgreSQL headers it builds against (cosmopolitan, pgvector, timescaledb) | 4 |
| A variadic target declared without its `...` (lemon's `ErrorMsg`, #416) | 1 |
| A header that does not compile on its own (secp256k1 in go-ethereum) | 1 |

## What it found

The two zlib failures and the lemon `ErrorMsg` failure are not K&R
problems. An ANSI definition hits the same two bugs: a storage class spelled
through a macro reaches the harness's `extern` declaration (#415), and a
variadic target is declared without its `...` (#416). Both are filed and
fixed separately.

The re-run reported no new findings.
